# AI 翻譯學習引導與費用控制設計

## 目標

擴充現有 `AI 翻譯朗讀`，讓學生除了看到翻譯，也能理解翻譯理由與英文句子的自然念法，同時降低 Gemini API 使用量。

## 使用者體驗

翻譯成功後直接顯示以下內容：

1. 原文與翻譯。
2. `為什麼這樣翻`：使用繁體中文簡短說明語意、句型與自然表達。
3. `重要片語`：最多三組英文片語與繁體中文意思。
4. `英文怎麼念`：將英文句子依語意分段，使用 `/` 表示短暫停頓，並以粗體標示建議重讀字。
5. 沿用現有英文正常速度朗讀，不新增慢速朗讀。

英翻中時分析英文原文；中翻英時分析英文翻譯。介面不顯示中文諧音或 IPA，避免學生形成錯誤發音習慣。

## 輸入與費用限制

- 英文最多 20 個單字。
- 中文最多 20 個 CJK 字元。
- 混合語句同時檢查英文與中文限制，任一超過即拒絕。
- 每個瀏覽器每 60 秒最多開始一次 Gemini 翻譯請求。
- 通過本地輸入、安全與 API Key 檢核後，由 service 在第一次 `fetch` 前觸發 `onRequestStart`，元件收到後記錄時間。
- Gemini 回傳錯誤、逾時或被供應商拒絕仍計入冷卻，因為請求已經送出。
- 空白、超長、本地判定不合宜或缺少 API Key 不計入冷卻。
- 冷卻期間停用送出按鈕並顯示剩餘秒數，例如 `請等待 42 秒`。
- 重新整理頁面後仍保留剩餘冷卻時間。

冷卻時間使用單一 `localStorage` 時間戳記。這是前端費用保護與誤觸防護，不是不可繞過的伺服器安全限制；現有功能使用使用者自己的 Gemini Key，且沒有登入識別，因此不新增後端限流服務。

## Gemini 回傳契約

翻譯、內容安全判斷與教學資料使用同一次 Gemini 請求。安全回傳包含：

- `sourceLanguage`
- `targetLanguage`
- `safe`
- `reason`
- `translation`
- `explanation`
- `keyPhrases`：最多三筆 `{ english, meaning }`
- `pronunciationSegments`：英文語意分段，每段包含原文與建議重讀字

說明必須使用適合學生的繁體中文，內容簡短、具體，不產生額外例句。Gemini `maxOutputTokens` 從目前的 1400 降為 700。

本地端嚴格驗證：

- 所有必要欄位存在，且沒有未知欄位。
- 翻譯語言、文字類型與長度正確。
- `explanation` 不可空白，最多 240 個字元。
- `keyPhrases` 最多三筆，英文與意思皆不可空白且各自最多 80 個字元。
- `pronunciationSegments` 最多六段，必須依序對應英文原句或英文翻譯中的實際文字。
- 重讀字必須存在於所屬英文分段。
- 翻譯與教學文字重新通過既有安全掃描。
- 不合格回傳一律不顯示、不複製、不朗讀。

不使用 Gemini `responseSchema.additionalProperties`，避免再次觸發不相容的 400 錯誤；未知欄位由本地端驗證拒絕。

## 元件與資料流

### `translationService.js`

- 將英文與中文上限改為 20。
- 擴充 Gemini prompt、response schema 與解析器。
- 驗證教學資料、安全性及發音分段與英文句子的關係。
- 在本地檢核完成且即將第一次呼叫 `fetch` 時觸發可選的 `onRequestStart`。
- 維持單次 API 呼叫及既有模型 fallback。

### `TranslationReader.jsx`

- 管理 60 秒冷卻時間與倒數顯示。
- 只保存最後請求時間，不保存原文、翻譯或教學內容。
- 翻譯成功後在結果區下方直接展開學習引導。
- 桌機維持原文與翻譯雙欄，學習引導使用全寬區域。
- 手機維持單欄，按鈕與長文字不可溢出或被底部裁切。
- 發音分段只作為閱讀提示；朗讀仍播放完整英文句子。

## 發音顯示

範例：

`I **WANT** to eat **HOT POT** / but I **DON'T** want to smell like it.`

- `/` 只表示自然停頓，不送入語音 API。
- 粗體只作為視覺重音提示。
- `朗讀英文` 使用原本完整、未加標記的英文句子。
- 沿用現有英文 TTS 速度與路徑。

## 隱私與儲存

- 不寫入 DB。
- 不儲存輸入、翻譯、解釋、片語或發音引導。
- `localStorage` 僅新增 `eg_translation_last_request_at`，內容為最後 Gemini 翻譯請求的毫秒時間戳記。
- 清除輸入不清除冷卻，避免用清除按鈕繞過限制。

## 錯誤處理

- 超過 20 words：顯示目前單字數與 20 words 上限。
- 超過 20 中文字：顯示目前字數與 20 字上限。
- 冷卻中：不呼叫 Gemini，顯示剩餘秒數。
- 舊請求取消或結果過期：不得更新畫面。
- Gemini 回傳缺少教學欄位或內容無效：顯示通用暫時無法使用訊息。
- 不向使用者顯示供應商內部錯誤或原始安全判定原因。

## 測試與驗收

- 驗證英文 19、20、21 words 邊界。
- 驗證中文 19、20、21 字邊界。
- 驗證一次 Gemini 請求同時回傳翻譯與教學內容。
- 驗證未知欄位、空白說明、過多片語、錯誤重讀字與不安全教學內容會被拒絕。
- 驗證首次有效請求寫入時間戳記，60 秒內不再呼叫 API。
- 驗證 API 失敗仍有冷卻，本地驗證失敗不產生冷卻。
- 驗證重新掛載元件後仍顯示剩餘倒數。
- 驗證不儲存任何句子或翻譯結果。
- 驗證英文朗讀仍使用既有正常速度與完整英文文字。
- 完整 Vitest、Vite build、桌機與 390x844 手機瀏覽器 QA 通過。
